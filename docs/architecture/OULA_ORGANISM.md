# OULA Organism Architecture

OULA is engineered as a digital organism. The metaphor is operational: each body system maps to a concrete software responsibility.

| Organism | Software responsibility |
|---|---|
| Mind | Decision, causal, predictive and optimization intelligence |
| Brain | Intelligence Kernel, models, context, memory and simulation |
| Heart | Event/workflow core and transactional state changes |
| Nervous system | APIs, events, messaging and integration contracts |
| Blood | Trusted data, commands and domain events with provenance/context |
| Skeleton | Domain model, bounded contexts and contracts |
| Muscles | Application services, workflows and transaction execution |
| Senses | User input, documents, GIS, external observations and future IoT |
| Immune system | IAM, policy, compliance, fraud/security detection and CI gates |
| Memory | Operational history, audit, outcomes and future Built World Memory |
| Lungs | Integration fabric to government, finance, maps and partner systems |
| Skin | API gateway/WAF/rate limiting boundary in deployment architecture |

## Core flow

\`\`\`text
People/Life
   -> Intent
   -> Property + Market + Truth
   -> Matching / LifeFit
   -> Decision
   -> Transaction
   -> Outcome
   -> Learning
\`\`\`

## Canonical rules
- Domains own truth; the Intelligence Kernel reads, reasons and proposes.
- Recommendation is not decision.
- Simulation is not reality.
- AI inference is not verified truth.
- Every sensitive action is attributable to an actor, purpose and authority.
